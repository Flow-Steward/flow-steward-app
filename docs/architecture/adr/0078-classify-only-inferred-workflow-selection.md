# ADR 0078 Классификатор задачи только для выбора, которого никто не сделал

Status: Accepted

Date: 2026-11-21

## Контекст

Перед каждым запуском узел маршрутизации вызывал классификатор задачи:
отдельный запрос к модели проекта, который возвращает пять меток —
`effort_hint`, `risk_level`, `automation_recommendation`, `confidence` и
пояснение. Классификатор появился, когда он выбирал workflow для задачи.

Теперь workflow всегда называет тот, кто запускает: форма оператора, API,
расписание, webhook, триггер провайдера, повтор, родительский workflow.
Запуск без `workflow_id` отклоняется до оркестрации. Поэтому от ответа
классификатора остаётся:

- `confidence` описывает выбор workflow; для названного workflow гейт
  автономности её уже не учитывает;
- `automation_recommendation` задаёт режим автономности по умолчанию, если
  проект его не задал. `supervised` названный workflow не останавливает; только
  `human_only` ставит каждый шаг на ручное подтверждение — то есть модель
  сама, недетерминированно, решает остановить запуск;
- `effort_hint` попадает в блок «Execution Mode» промпта агента, а все метки
  доступны workflow как переменные.

Цена — 3–4 секунды и токены модели на каждый запуск, включая workflow без
единого AI-шага. На распознавании чека это была шестая часть времени.

## Решение

1. Модель классифицирует задачу только тогда, когда workflow выбран не
   вызывающим. Для источников из `EXPLICIT_WORKFLOW_SELECTION_SOURCES`
   классификация детерминированная, без запроса к модели:
   `effort_hint=standard`, `risk_level=medium`,
   `automation_recommendation=supervised`, `confidence=1.0`, пояснение
   `explicit_workflow_selection`.
2. Решение человека задаётся явно: шагом Approval в workflow, который автор
   ставит там, где оно нужно, и политикой автономности проекта или шага. Модель
   больше не может сама поставить запуск на ручное подтверждение.
3. `provider_trigger` и `rerun` — явный выбор: триггер провайдера привязан к
   одному workflow, повтор запускает workflow своего job. Они входят в
   `EXPLICIT_WORKFLOW_SELECTION_SOURCES` и сохраняют свою метку источника
   (раньше узел маршрутизации переписывал её в `explicit_request`).
4. Там, где классификатор всё же вызывается, он работает с глубиной
   рассуждений `low`: пять меток не требуют размышлений. Проект может задать
   классификатору свою глубину в `agents_config.agents.config.classifier`.

## Последствия

- Запуск названного workflow не делает лишнего запроса к модели: быстрее на
  3–4 секунды и дешевле, в том числе у workflow без AI-шагов.
- Проект без режима автономности, который раньше получал паузы от
  `human_only`, теперь их не получает. Нужная пауза ставится шагом Approval
  или режимом `manual` у проекта или шага.
- Метки в промпте и переменных у названного workflow постоянные
  (`standard`/`medium`); workflow, который на них ветвился, видит всегда одни
  и те же значения.
- Повтор сохранённого запуска с уже записанными метками (`resume`, повторная
  доставка) использует их как раньше.
