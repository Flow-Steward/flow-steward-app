## Flow Steward 0.9.12

### Workflow reports

- Create structured reports in the **Template** step with a no-code editor: text, metrics, tables, line/bar charts, and sections, with typed number, currency, and date formatting.
- Select a workflow's report output and view its persisted report on the **Job Result** page. Historical reports use the saved run output rather than the workflow's current definition.
- Expose reports through the new `workflow_run_report` MCP tool and bundled MCP Apps viewer for compatible clients. Forward validated child-workflow reports through **Invoke**, while keeping full report datasets out of diagnostic messages.

### Faster large workflows and a more responsive builder

- Reduce repeated readiness work when opening workflows with many steps; find linked projects in one request.
- Improve initial rendering and canvas responsiveness during dragging on large workflows.
- Open the affected step or hook frame directly from a validation issue. Improve connection routing around cards and keep grid navigation inside the application.

### MCP tools and AI agent setup

- Preserve complete MCP JSON Schemas, including complex nested parameters, in both AI agents and deterministic workflow steps.
- Add **Microsoft 365 Copilot** setup on **Settings → Account → AI agents**, including a generated declarative-agent package and administrator-managed OAuth clients.
- Improve cloud AI client OAuth interoperability by correctly fetching and validating published client metadata.
- Clarify MCP connection and extension-tool labels in the workflow editor.

### Jobs and dashboard

- Add date-range filtering to Jobs and fix moving selected jobs to Trash.
- Remove internal monetary accounting and its cost displays from operational views; reorganize the dashboard's attention queue.

### Extension connections, installation, and upgrades

- Add the Core connection flow for extensions that explicitly support importing an existing OAuth refresh token, using extension host contract **1.6**.
- Use published, version-pinned application images for production installation and release upgrades instead of building application images on the customer's server.
- Raise the default release-upgrade handoff timeout from 60 to 180 seconds, including service startup.
- Correct installer image-pool and CLI handoff handling, update host autostart configuration, and align installation and upgrade documentation with the official-image flow.

[Full changelog: 0.9.11 → 0.9.12](https://github.com/Flow-Steward/flow-steward-app/compare/v0.9.11...v0.9.12)

**Upgrade note:** When starting a cold upgrade with the 0.9.11 CLI, use `--timeout-seconds 180`; this release uses 180 seconds by default. Follow the backup, maintenance, and database-upgrade procedures in the [upgrade guide](https://github.com/Flow-Steward/flow-steward-app/blob/v0.9.12/docs/GUIDE.md#maintenance-and-release-upgrade).
