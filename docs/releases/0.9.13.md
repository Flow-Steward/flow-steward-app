## Flow Steward 0.9.13

### Workflow reports in AI chats

- Fix an empty MCP Apps report viewer when a report contains a line or bar chart. The single-file viewer is assembled after Vite's final import analysis, and its build check rejects unresolved build placeholders.

### Installation and host configuration

- Simplify the installation wizard with explanations of Compact and Scalable, SeaweedFS selected by default, and technical overrides available through Advanced settings.
- Show only compatible website-access and TLS choices, avoiding configurations such as an existing reverse proxy combined with an application-managed certificate.
- Print complete Nginx or Apache configuration examples and the remaining proxy/certificate setup instructions at the end of installation.
- Resume an interrupted installation using its saved profile and settings, including Scalable installations stopped during preflight before configuration files were created.
- Enable `config show`, `config set`, `config validate`, and `config apply` on Compact through the installed management image. Operators can update the public domain and host settings without switching deployment profiles.

### Release upgrades and recovery

- Increase the default installer-handoff budget in the 0.9.13 CLI from 180 to 1,800 seconds, allowing more time for image preparation and service startup with the standard `./flow-steward release upgrade` command.
- Report installer startup and handoff timeout failures with a specific cause, an operation identifier, a diagnostic log when available, and instructions for resuming the saved target version.
- Keep an existing reverse proxy running during upgrades: check the application's private backend ports instead of treating the proxy's public TLS port as a conflict. Scalable also checks its private MCP backend port.
- Verify the final Scalable CLI runtime identity before recording the new installed release, avoiding a successful upgrade followed by a CLI/stack identity mismatch in Doctor.

### Remote MCP responses

- Add the host setting `FS_MCP_HTTP_RESPONSE_MAX_BYTES` for the complete remote MCP HTTP response body, including JSON and SSE envelopes. The default remains `4194304` bytes (4 MiB); the supported range is 1 KiB to 1 GiB.
- Deliver the setting to Scalable application/worker services and Compact child processes. For example, allow 32 MiB with `./flow-steward config set FS_MCP_HTTP_RESPONSE_MAX_BYTES=33554432`, then `./flow-steward config apply --confirm`.
- Explain oversized MCP tool responses with the configured byte limit and the setting name, without including remote response content in the error.

### Upgrade notes

Official installation and upgrade use prepared images, including the installer.
Source builds require explicit `--from-source`; an unavailable image does not
trigger an automatic source-build fallback.

The longer upgrade default belongs to the **0.9.13 caller**. Starting an upgrade
with an older CLI still uses that CLI's existing timeout; downloading the target
installer does not retroactively change the caller's budget.

Maintenance remains enabled after an upgrade until the operator explicitly
disables it following verification. Follow the backup, maintenance, and database
procedures in the [upgrade guide](https://github.com/Flow-Steward/flow-steward-app/blob/v0.9.13/docs/GUIDE.md#maintenance-and-release-upgrade).
