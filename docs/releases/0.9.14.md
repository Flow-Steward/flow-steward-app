## Flow Steward 0.9.14

### Date and time formats

- Each user can choose a date format (`D MMM YYYY`, `MMM D, YYYY`, `DD.MM.YYYY`, `DD/MM/YYYY`, `MM/DD/YYYY` or `YYYY-MM-DD`) and a 24-hour or 12-hour clock in their profile, next to the timezone. A preview line shows the result before saving.
- Every date and time in the interface now uses these settings, so the same time no longer appears in different formats on different pages. Month names follow the interface language. The job overview's Started and Last update times now use the reader's timezone and format instead of server UTC.
- Workflow reports keep their own locale and timezone.

### Runs and job details

- The run view follows the 2026-11-08 design review. "Execution waterfall" is renamed "Execution steps", Step details no longer repeats the summary or the status, and Model usage shows the total as "Tokens: N" again.
- A long run's step history pages load in the background instead of blocking the page, and the run canvas reuses the page's step history instead of requesting it again. Opening a large run triggers fewer short loading pauses.
- Workflow runs are faster as they grow. Each additional step costs about the same as the first, where previously the per-step time grew with the number of steps already run. On a 200-step run, the last steps take about 1 ms each instead of 16–40 ms.

### Workflow builder

- A live **Run workflow** started from the builder is followed on the canvas like a Test Run: the dialog closes, and the run bar shows the run's progress and labels it as a live run.
- A connector step whose connection was deleted or re-created can be moved to another connection and saved. The editor shows the connection the step will actually use, and saving updates every stored copy of the step's connection.
- Wrapped connection lines enter their target rows from above.

### Dashboard

- The five status cards sit in one row. A card showing zero is drawn in a muted style, and Failed / Stuck reads "Right now · oldest failing …" because it is a live count that the date range does not limit.
- The Attention queue is a regular dashboard panel. Rows are named by their workflow, list the oldest first, and end with a single "Open queue · N more" link.

### AI agents setup

- Settings › Account › AI agents is a numbered step-by-step setup. Finished steps collapse to the choice made, with a Change link. Clients are grouped into "On your computer" and "In the cloud", and cloud clients link to Connected AI apps.
- The token step keeps the token's state, preset, projects and expiry together, with Create another token and an inline Revoke confirmation. Copy buttons show "Copied" in place instead of a notification.

### Loading states

- Every loading state follows the design system's loader rules. A loader appears only after 400 ms and stays for at least 500 ms, so fast requests no longer flash.
- Buttons that start an action show a busy label such as "Saving…" with a small loader. The button ignores repeated presses at once and keeps its width.

### MCP

- New `project_connections` tool lists the connections that a project's workflow steps can use. It requires the `projects.read` scope. The public MCP tool count is now 74.

### Interface

- Orange accent buttons use white text in the dark theme.

### Installation on Docker Desktop

- `./install.sh` now checks that Docker Desktop shows current files from the installation folder before it starts the installer container. When Docker Desktop shows stale files, the installer stops with exit code 7 and explains what to do: restart Docker Desktop, or switch Docker Desktop's virtual machine manager to Apple Virtualization framework if the problem returns.

### Railway, Fly.io and Render

- Compact on Railway, Fly.io and Render starts again. These platforms run RabbitMQ as a separate service on the provider's private network. Flow Steward refused that plaintext broker connection, so the documented installations restarted in a loop.
- New RabbitMQ transport mode `platform-private` allows plaintext AMQP only to the one host named in `FS_RABBITMQ_PRIVATE_HOST`, on port 5672. Any other broker still needs verified TLS. The installer and the Compose files never select this mode. [ADR 0064](https://github.com/Flow-Steward/flow-steward-app/blob/v0.9.14/docs/architecture/adr/0064-rabbitmq-platform-private-transport.md) describes what each provider's private network protects.

### Upgrade notes

This release adds the `date_format` and `time_format` columns to `users` with
migration `20261109150000_user_date_time_format.sql`. Existing users see
`D MMM YYYY` with a 24-hour clock until they choose otherwise.
Apply the migration during the upgrade as described in the
[upgrade guide](https://github.com/Flow-Steward/flow-steward-app/blob/v0.9.14/docs/GUIDE.md#maintenance-and-release-upgrade).
