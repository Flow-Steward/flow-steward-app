## Flow Steward 0.9.17

### Webhooks

- A webhook trigger with the Signed webhook (HMAC) auth mode now saves. The database refused that mode and the save answered HTTP 500.
- A webhook trigger saved through the operator or MCP tools with an unknown `idempotency_mode` is refused with a 400 that names `none` and `header`, instead of HTTP 500. File limits above the database maximum are capped as the body limit already was, and the API examples no longer show the invalid `client_key`.

### Extensions

- A skill shipped in an extension keeps its declared `expected_outputs` and `expected_inputs` when an agent runs it. The agent's answer schema had no place for the outputs, so every answer that carried them was refused with "Additional properties are not allowed".
- Saving a connection form no longer writes fields the form hides. A hidden number, integer or yes/no field keeps its stored value instead of being saved as an empty text, which the connection's schema refused when the form listed it in `config_fields`.
- A new connection whose required secret is chosen from the stored secrets now saves. The create request carries the choice, the required-secret check counts it, and the secret is bound before the connection is returned; if the binding is refused, the new connection is removed. The connection still needs approval before it uses the stored secret.
- The result of an action run from a component on an extension page shows right after that component, not at the top of the page, so the outcome of a long form's button is visible where it was pressed. A result no page component started stays at the top.
- When an action fails because a connection's stored secrets are not approved, the result explains it in plain words and points to Approve use of secrets on the connection's card, instead of showing the raw `secret_configuration_unapproved` failure.
- An operator can now load the data of an extension page. Running an extension query needed the administrator role, so the grids and stats of an extension page stayed empty for operators; a query now follows the rule of an action: operator or administrator, or a token with the scopes of an action write. A viewer still cannot run one.
- An action whose connection's stored secrets are not approved now answers HTTP 409 with the code `secret_configuration_unapproved` instead of a plain 400, and a picker field that lists resources through such a connection shows the same code instead of failing with a server error. Any other failure to resolve a picker's connection is reported as `connection_resolution_failed`.
- An extension query can now run with a project connection. A query in `ui/queries/queries.yaml` declares `connection: {connection_type_ids: [...]}` of the extension's own connection types; the host resolves the connection the page names in `target.connection_id` exactly as for an action and hands its configuration and secrets to the query, so an extension page can show data from the extension's own service. Such a query only reads, runs at most 30 seconds, and needs `runtime.compatibility.platform_min: 1.7.0`; a page that shows it declares the same `connection` key and may declare `refresh_seconds`. The compiler refuses a bundle that breaks these rules.
- The extension host contract is now 1.7.0 (the wire contract stays `extension_host_v2`).
- A long extension query no longer holds up other requests to the server while it waits for the extension: it runs off the request loop, as an action already did.
- `flowsteward-extension-sdk` 0.5.0 adds `connection_from_payload`, which reads the project connection of an action and of a page query through one call, as a `RuntimeConnection` whose printed form never shows its secrets.
- An extension page that declares a connection shows a connection selector next to the project selector. With one connection of the page's types it is chosen automatically; with several, the page waits until one is picked and keeps the choice in the address; with none, it says so and links to the extension's page for creating one. The page's queries, query buttons, actions and grid row actions use the selected connection, a row value never replaces it, and a connection whose stored secrets need approval shows the approval control. A viewer sees that only an operator or administrator can load the page's data.
- An extension page may declare `refresh_seconds` (10 to 3600) to reload its data on that interval while the browser tab is visible and no load is running. A failed load stops the automatic reload until the person presses the page's Refresh button, which a page that reads through a connection always shows.
- An extension page can take parameters from its address: `p.<name>` keys (for example `extension_page=run_detail&p.run_id=42`) are passed in the `params` of every query on that page, so an extension can link from a list to a detail page. Names are lowercase identifiers, at most 20 values of up to 1024 characters each; they are dropped when the person switches to another page.

### Security

- An extension page query now checks that the caller may reach the project its request names before the extension's declared runtime resources, such as that project's provider secrets, are resolved. A query naming a project of another account or outside the caller's projects is refused.
- A picker field that lists an extension's resources through a connection now passes the same reflected-secret check as an action: a result that contains one of the connection's secret values is withheld and reported as `extension_secret_exposure_blocked`.
- A query that runs with a connection is checked like an action before any secret is read: project access, account, project, extension, install, enabled state, connection type and the approval of stored secrets. Its target may hold only `connection_id`; a target with configuration or secrets, a target sent to a query without a connection, and a connection query without a target are refused. Its result passes the reflected-secret check before it is logged or returned, a response that asks for commands, events or project-state updates fails without applying them, and remote runtime installs cannot run it. The extension invocation log records the connection.
- An operator, viewer or service account must name a project for every extension query, as for an action.

### Upgrade notes

This release replaces the `auth_mode` check on `workflow_entrypoints` with
migration `20261113073401_webhook_signature_auth_mode.sql`, so it also allows
`webhook_signature`. Existing triggers are unchanged.
Apply the migration during the upgrade as described in the
[upgrade guide](https://github.com/Flow-Steward/flow-steward-app/blob/v0.9.17/docs/GUIDE.md#maintenance-and-release-upgrade).
