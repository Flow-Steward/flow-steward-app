## Flow Steward 0.9.18

### Quality gate (contributors)

- The hosted release gate runs Tier 3 on four parallel runners (backend, backend-frontend contracts, frontend, external checks) and then reads all of their results in one cumulative check; Sonar runs beside that check instead of after it.
- A release run imports the check results of the latest runs of its branch and of main. A check whose inputs a commit did not change is not run again, so a retry after a small fix no longer repeats the whole gate.
- The backend and frontend suites run only the tests a change reaches since the last result of the same suite: the backend records which files each test module executes and reads, the frontend uses `vitest related`. Tests that failed last time run again. A change to dependencies, the database schema, test configuration or the gate itself runs the whole suite, and a weekly run on main (and the `release-full` mode) runs every suite whole. See ADR 0068.
- The backend suite warms pytest's assertion-rewrite cache before its parallel workers start; collecting the suite takes about half as long.
- A daily job keeps the repository's Actions cache under 7 GiB and deletes release image archives older than three days.
