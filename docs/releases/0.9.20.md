## Flow Steward 0.9.20

### Improvements

- `release upgrade` now manages maintenance, a verified database backup, required
  migrations and healthy reopening in one command. Failed or interrupted upgrades
  keep maintenance enabled and resume the same target without repeating completed
  activation or replacing the original backup.
- `--skip-db-backup` explicitly allows an upgrade without a database dump. The
  waiver reaches database migration while retaining maintenance and writer safety
  checks. Compact stops its runtime writers before database migration.

Automatic orchestration requires CLI 0.9.20 or newer. For the initial update from
an older CLI, follow its printed manual recovery and maintenance instructions.

#### Upgrading from 0.9.19 or older

You can go straight to 0.9.20 from any earlier release; every pending
migration is applied in order. The first `release upgrade` still runs the
installed, older CLI, which may stop with `release_migration_required` after
switching the checkout to 0.9.20. From then on `./flow-steward` is 0.9.20's:

```bash
./flow-steward database upgrade --maintenance-confirmed --confirm
./flow-steward release upgrade --target-version 0.9.20 --confirm
./flow-steward maintenance disable --confirm
```

On Compact, `database upgrade` now stops `compact-runtime` itself, and the
repeated `release upgrade` no longer fails while the runtime is stopped.

#### An earlier Compact upgrade is stuck after `database upgrade`

Before 0.9.20, Compact read the maintenance state through the running
`compact-runtime`. Once the database had been migrated with the runtime stopped,
`release upgrade` failed with "An unexpected internal error occurred" and
`./install.sh` answered `release_upgrade_pending` (#28). 0.9.20 reads the state
without the runtime. To finish an upgrade that is already stuck this way, start
the runtime on the target release, then repeat the same upgrade (verified from
0.9.15 to 0.9.19):

```bash
cd infra/docker
docker compose -p flow-steward -f docker-compose.compact.yaml -f compact/ingress-bundled_traefik.yaml -f compact/tls-bundled-files.yaml -f compact/storage-bundled.yaml --env-file ../../.env.prod --profile storage-seaweedfs --profile cli up -d --no-deps --no-build --pull never compact-runtime
cd ../..
./flow-steward release upgrade --target-version <the pending version> --confirm
./flow-steward maintenance disable --confirm
```

Use the compose files and profiles your install log shows. `release info` then
reports the pending version as current; upgrade to 0.9.20 afterwards.

### Fixes

- MCP answers about runs and workflows now carry links an AI app can give the user. Asked for "the run page and the workflow editor", claude.ai could only quote ids, because no tool returned either link. `workflow_trigger`, `job_status`, `job_result`, `workflow_run_report`, the approval, incident, error and cancel tools, and every row of `job_list`, `project_jobs` and `job_approvals_pending` now include `job_url`, the run's page; `job_restart` also gives `new_job_url`. `workflow_list` rows, `workflow_definition`, `workflow_contract`, `workflow_validate`, `workflow_stats`, `workflow_set_enabled` and `workflow_apply_changes` include `editor_url`, the workflow editor. The links use the installation's public address (`FS_PUBLIC_BASE_URL`); without it they stay paths. Only the id each tool is about becomes a link: step ids and ids inside workflow data stay as they are.
- Browser tabs now show the Flow Steward logo. The page previously requested
  `/app/favicon.svg`, where the server returned the application HTML instead of
  an image. The favicon is now included among the versioned frontend assets;
  the fallback icon uses the same Flow Steward artwork.
- The installation guide and the checkout reference cloned `v0.9.12`, so an
  installation that followed the guide got a release seven versions old. Every
  documented clone command now names the current release, and a test keeps them
  equal to `VERSION`.
- Creating an agent, tool or skill starts with its **Display Name**, now
  required for agents too. The **Agent ID**, **Tool ID** or **Skill ID** below
  it fills in from the name (`Order Sync (EU)` becomes `order_sync_eu`) and can
  still be changed. Accented letters no longer split a word in generated IDs,
  including workflow IDs (`Café résumé` becomes `cafe_resume`).
- Flow Steward no longer sends `Strict-Transport-Security` when it is opened
  through `localhost`, a `*.localhost` name or an IP address. Browsers keep
  that policy per host name for every port, so a trusted local certificate
  would have forced HTTPS on every other app the user runs on `localhost` for
  two years. Domain names keep the header.
- Compact: the bundled Traefik comes back after a host or Docker Desktop restart.
  It used to read its start script, routing template and certificate straight
  from the installation folder; on Windows, Docker Desktop could start it before
  the WSL distribution holding that folder was available, the container failed
  with `Exited (127)`, and Docker never tried again, so the public URL stayed
  down for days. A one-off `traefik-files` container now copies those files into
  a Docker volume on every start of the stack, and Traefik reads only that
  volume (#27).
- `flow-steward status` on Compact also checks that the bundled Traefik accepts
  connections, instead of saying `ready` while the public URL is unreachable
  (#27).
- Every `doctor` repair hint includes `--confirm`, so the printed command
  repairs instead of answering "Rerun with --confirm" (#27).
- `config set` followed by `config apply` now reaches the running containers.
  Docker Compose prefers its own process environment over the env file, and the
  management container still carried the value from before the apply, so a
  setting such as `FS_ALLOW_PRIVATE_REMOTE_URLS` reached `.env.prod` while the
  runtime kept the old value and was not even recreated. The installation's env
  file now wins for every setting it names (#30).
- `doctor` fails a new `stack_unhealthy` check when a running service, such as
  the bundled SeaweedFS, fails its healthcheck. It used to report no problems
  while storage was `unhealthy` for hours (#26).
- An unexpected error in a CLI command now writes its traceback, with secrets
  redacted, to the operation log. A failed upgrade review used to log only
  `internal_error`, with nothing anywhere saying what failed (#28).
- When `database upgrade` is refused because the previous release is still
  connected, the advice says that Compact stops `compact-runtime` itself too, not
  only the Scalable processes (#28).
- The **Hide acknowledged** checkbox on **Jobs** is centred with the filter
  controls beside it instead of sitting above them (#25, contributed by Tatiana
  Andrusenko).
