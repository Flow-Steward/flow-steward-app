## Flow Steward 0.9.22

### Fixes

These came out of testing upgrades from 0.9.12 and 0.9.15 to 0.9.20 and 0.9.21 on
Compact. None of them stopped an upgrade, but each one made it harder to tell
what was going on.

- Compact: `database upgrade` now says that it stops `compact-runtime` and that the
  runtime stays stopped until the release upgrade starts the new release. Before,
  it stopped the runtime without saying so.
- Log paths are now host paths inside the installation folder.
  - Compact `database upgrade` used to print `Log: /app/logs/cli/...`. That path
    was inside a one-shot container and was deleted when the container exited.
    The log is now kept in `.flow-steward/logs/cli` and reported there.
  - Paths inside the Compact CLI container's state directory
    (`/run/flow-steward-install-state/...`), such as the log of a failed
    `release upgrade`, are now reported under the installation's `.flow-steward`
    directory.
- `release info` now shows an unfinished upgrade. It reports `upgrade_pending`,
  the release that is waiting to be applied, and the command that resumes the
  upgrade. Before, it showed only the installed release.
- Compact: `status` now explains a stopped runtime. Before, while an upgrade was
  stuck after `database upgrade`, it said only `health probe failed (gaierror)`.
  Now it names the unfinished upgrade and the `release upgrade` command that
  completes it. If no upgrade is pending, it says that `compact-runtime` is not
  running and gives the command that starts it.
- `"still working"` lines no longer appear after a step has finished. A step's
  last heartbeat could arrive after its ✓ line, put the step back on the list of
  running steps, and keep the notes coming until the command ended.
- The summary line of `doctor` now suggests
  `./flow-steward doctor --fix <ids> --confirm`. It used to leave out `--confirm`,
  so the pasted command changed nothing when run without a terminal. The JSON
  `fix_command` now includes `--confirm` too.
- `./install.sh` and `release upgrade` now make installation state readable by its
  owner only, including state that an older release left readable by others.
  0.9.15 on Docker Desktop left `.flow-steward/.docker-desktop-mount-probe` at
  0644. `doctor`'s `secrets_modes` check failed on it until
  `doctor --fix secrets_modes --confirm` was run.
- `database preflight` now exits with code 4 when the upgrade is blocked. It lists
  each blocking issue the same way `database upgrade` does. Before, it listed the
  issues and exited 0, so `database preflight && database upgrade` went on to an
  upgrade that was then refused.
