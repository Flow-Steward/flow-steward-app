## Flow Steward 0.9.23

### Fixes

#### Switching between Compact and Scalable

- `./install.sh --deployment-profile scalable` on an installed Compact, and
  `--deployment-profile compact` on an installed Scalable, failed every time with
  `lifecycle_operation_active` and then `profile_switch_apply_failed`, even when
  nothing else was running. The installer keeps its own lock for the whole switch,
  and the `config apply` it starts also took that lock, so the switch refused
  itself. The installer now lends its lock to that one `config apply` for as long
  as it runs. Every other command is still refused while `./install.sh` runs, and
  the refusal now says that `./install.sh` holds the lock.
- A failed switch left the installed release recorded as pending for the other
  profile. After that, every `./install.sh` stopped with `release_upgrade_pending`,
  and `release upgrade` and `release check` stopped with
  `release_target_context_mismatch`, whatever version was asked. A failed switch
  that left nothing to continue now removes that record. If an interrupted switch
  left one, for example because the installer was killed:
  - `./install.sh --deployment-profile <target profile>` finishes the switch;
  - `release check` and `release upgrade` stop with `profile_switch_unfinished` and
    print that command.
- A failed switch also left its pending configuration change behind, and the next
  `config apply` run for any other reason would have carried out the switch. That
  change is now removed together with the record above. A pending change written
  after the switch is kept.
- After a failed switch, the message no longer says that the switch was journaled
  and can be continued when nothing was journaled.
- Scalable to Compact stopped before changing anything with
  `core_image_preparation_failed` ("Docker Compose could not resolve infrastructure
  images"). The installer resolved the Compact images against the installed
  Scalable settings, which have no `FS_WORKER_PROCESSES` and, on an installation
  that was never Compact, no Compact image. It now resolves them after it builds
  the Compact image, with the settings the switch writes for Compact.
- During Scalable to Compact the public address was down for about a minute: the
  switch started Compact's Traefik without first copying the files it starts
  from, so Traefik restarted in a loop until a later step copied them. A switch
  run with `config apply` alone, without `./install.sh`, could have left it down.
  A switch now runs those one-time preparation services first.
- A switch that had finished could still end with `container_unhealthy`
  ("rabbitmq-fs: state=running, health=starting"), because the installer checked
  the services it had just restarted without waiting for their healthchecks. It
  now waits while a healthcheck is still starting. The same applies after
  `./install.sh` or `doctor` starts services that were stopped.
- After Scalable to Compact with maintenance enabled, which is the documented
  procedure, `./flow-steward maintenance status` and
  `maintenance disable --confirm` failed with `maintenance_state_invalid`, so
  maintenance could not be turned off. The switch copied the maintenance state into
  the Compact data volume with an owner that the Compact maintenance commands cannot
  read. It now writes it with the owner Compact uses itself.

#### Before you upgrade an installation where a switch failed

A failed switch on 0.9.21 or 0.9.22 may have left
`.flow-steward/pending-release.json`. Check whether that file names the installed
version on the other profile. If it does, move it aside before you upgrade, for
example to `pending-release.json.stale`: the 0.9.21 and 0.9.22 CLIs refuse the
upgrade while it is there. Then upgrade to 0.9.23 and run the switch again.

A failed switch may also have left `.flow-steward/pending-config.json`.
`./flow-steward config show` lists it as a pending change. If it names the other
profile, the next `config apply` performs the switch. Rerunning the switch on
0.9.23 replaces that file. If you do not want to switch, move it aside as well.
