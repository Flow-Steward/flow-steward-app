## Flow Steward 0.9.25

A fix release for upgrades of Scalable installations.

### Fixes

- **Release upgrades apply their migrations on Scalable.** `release upgrade` applies
  the target release's database migrations in a one-shot container of `fs-app`. That
  container had no writable place for the command's operation log. The migration
  command stopped at once, and the upgrade stopped at *Apply the target release's
  database migrations* with `release_database_upgrade_failed`. Maintenance stayed on.
  It affected every Scalable upgrade whose target release carries migrations,
  including upgrades to 0.9.23 and 0.9.24. Compact installations were not affected.
- **The real reason is shown.** When a command in a container fails, the upgrade now
  reports the command's own error code and message. Before, it showed Docker's
  "Container … Created" progress lines instead.

### Upgrading

`./flow-steward release upgrade --confirm`, as usual. On Scalable this is the first
release whose own migrations a release upgrade can apply.

### If an earlier upgrade stopped at the migration step

A Scalable installation whose upgrade to 0.9.23 or 0.9.24 stopped with
`release_database_upgrade_failed` keeps resuming that upgrade, and stays in
maintenance. To finish it:

1. In the installation folder, open `infra/docker/docker-compose.prod.yaml`. In the
   `fs-app:` service, under `environment:`, right after the line
   `<<: [*app-worker-environment, *installation-mode-environment]`, add:

   ```yaml
         FS_CLI_OPERATION_LOG_ROOT: /app/logs/cli
   ```

2. Run `./flow-steward release upgrade --confirm`. It resumes the stopped upgrade,
   applies the migrations, starts the services and turns maintenance off.
3. Undo the edit: `git checkout -- infra/docker/docker-compose.prod.yaml`.
4. Upgrade to 0.9.25: `./flow-steward release upgrade --confirm`.
